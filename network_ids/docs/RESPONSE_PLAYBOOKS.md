# NIDS Incident Response Playbooks
# ============================================================

## Overview

This document contains standardized incident response playbooks for alerts generated by the NIDS platform. Each playbook follows the NIST SP 800-61 Incident Handling Framework: Preparation → Detection & Analysis → Containment → Eradication → Recovery → Post-Incident Activity.

## Playbook Structure

Each playbook contains:
- **Trigger Conditions**: What alerts initiate this playbook
- **Severity**: Critical / High / Medium / Low
- **Estimated Timeline**: Expected duration
- **Required Roles**: SOC Analyst, IR Lead, Network Admin, etc.
- **Prerequisites**: Tools, access, authorization
- **Phase 1: Detection & Analysis** (0-30 min)
- **Phase 2: Containment** (30 min - 2 hours)
- **Phase 3: Eradication** (2-8 hours)
- **Phase 4: Recovery** (1-24 hours)
- **Phase 5: Post-Incident** (24-72 hours)
- **Runbook Checklist**: Step-by-step verification
- **Escalation Criteria**: When to escalate

## Playbook 1: Web Application Attack (SQL Injection, XSS, Command Injection)

### Trigger Conditions
- Rule IDs: 1000001-1000012 (Web App Attacks)
- Severity: Critical / High
- Source: Suricata HTTP alerts

### Severity: Critical / High
### Estimated Timeline: 2-6 hours

### Required Roles
- SOC Analyst (Lead)
- Web Application Owner
- Database Administrator
- Network Administrator

### Prerequisites
- Access to WAF/load balancer
- Database query logs
- Application logs
- Authority to block IPs

---

### Phase 1: Detection & Analysis (0-30 min)

| Step | Action | Owner | Verification |
|------|--------|-------|--------------|
| 1.1 | Acknowledge alert in SIEM/SOAR | SOC Analyst | Alert assigned |
| 1.2 | Extract attack details: source IP, target URL, payload, timestamp | SOC Analyst | Details documented |
| 1.3 | Check if source IP is whitelisted | SOC Analyst | Whitelist check complete |
| 1.4 | Retrieve HTTP request/response from logs | SOC Analyst | Request/response captured |
| 1.4 | Correlate with other alerts from same source IP | SOC Analyst | Correlation complete |
| 1.5 | Check threat intel for source IP reputation | SOC Analyst | Reputation documented |

**Decision Point**: Is this a confirmed attack or false positive?
- **Confirmed Attack** → Continue to Containment
- **False Positive** → Document, tune rule, close alert

---

### Phase 2: Containment (30 min - 2 hours)

| Step | Action | Owner | Verification |
|------|--------|-------|--------------|
| 2.1 | Block source IP at perimeter firewall | Net Admin | Block confirmed in firewall |
| 2.2 | Block source IP at WAF | Web App Owner | WAF rule deployed |
| 2.3 | Enable enhanced logging for target application | App Owner | Enhanced logging active |
| 2.4 | Review WAF rules for similar attack patterns | Sec Engineer | WAF rules reviewed |
| 2.5 | Enable rate limiting for target endpoint | App Owner | Rate limiting active |

**Escalation**: If attack is ongoing and cannot be blocked within 1 hour → Escalate to IR Lead

---

### Phase 3: Eradication (2-8 hours)

| Step | Action | Owner | Verification |
|------|--------|-------|--------------|
| 3.1 | Review application logs for successful exploitation | App Owner / DBA | Log review complete |
| 3.2 | Check database for unauthorized queries/modifications | DBA | No unauthorized changes |
| 3.6 | Check for webshells/backdoors on web server | Sec Engineer | No webshells found |
| 3.4 | Rotate compromised credentials (if any) | App Owner / Sec Engineer | Credentials rotated |
| 3.5 | Apply security patches if vulnerability exploited | App Owner / Sec Engineer | Patches applied |
| 3.6 | Update WAF rules with attack signatures | Sec Engineer | WAF updated |

---

### Phase 4: Recovery (1-24 hours)

| Step | Action | Owner | Verification |
|------|--------|-------|--------------|
| 4.1 | Restore from clean backup if data modified | DBA / App Owner | Restore verified |
| 4.2 | Re-enable monitoring with enhanced rules | SOC Analyst | Monitoring active |
| 4.3 | Conduct application penetration test | Sec Team | Pentest scheduled |
| 4.4 | Update incident documentation | SOC Analyst | Documentation complete |

---

### Phase 5: Post-Incident (24-72 hours)

| Step | Action | Owner | Verification |
|------|--------|-------|--------------|
| 5.1 | Conduct root cause analysis | IR Lead | RCA complete |
| 5.2 | Update detection rules based on attack | Sec Engineer | Rules updated |
| 5.3 | Update WAF rules | Sec Engineer | WAF updated |
| 5.4 | Conduct lessons learned meeting | IR Lead | Meeting held |
| 5.4 | Update incident response plan | IR Lead | Plan updated |

---

### Runbook Checklist

- [ ] Alert acknowledged and assigned
- [ ] Source IP identified and reputation checked
- [ ] Attack payload analyzed
- [ ] Source IP blocked at firewall/WAF
- [ ] Application logs reviewed for exploitation
- [ ] Database checked for unauthorized access
- [ ] Credentials rotated if compromised
- [ ] Patches applied
- [ ] WAF/IDS rules updated
- [ ] Stakeholders notified
- [ ] Documentation complete
- [ ] Lessons learned scheduled

---

### Escalation Criteria
- Multiple critical web apps targeted
- Data exfiltration confirmed
- Attacker pivoted to internal network
- Unable to contain within 2 hours
- Regulatory notification required (GDPR, HIPAA, etc.)

## Playbook 2: Malware C2 Communication / Botnet Activity

### Trigger Conditions
- Rule IDs: 1000201-1000203 (Malware C2, DNS Tunneling, Suspicious User Agent)
- Severity: Critical / High

### Severity: Critical
### Estimated Timeline: 4-24 hours

### Required Roles
- SOC Analyst (Lead)
- Incident Response Lead
- Endpoint Security Team
- Network Administrator
- Threat Intelligence Analyst

### Prerequisites
- EDR/EDR access
- Network capture capability
- Malware analysis sandbox
- Authority to isolate hosts

---

### Phase 1: Detection & Analysis (0-30 min)

| Step | Action | Owner |
|------|--------|-------|
| 1.1 | Identify compromised host(s): IP, hostname, user | SOC Analyst |
| 1.2 | Determine C2 type: HTTP, DNS, custom protocol | SOC Analyst |
| 1.3 | Extract IOCs: IPs, domains, hashes, user agents | SOC Analyst |
| 1.4 | Check threat intel for C2 infrastructure | Threat Intel |
| 1.5 | Identify all hosts communicating with C2 | SOC Analyst |

---

### Phase 2: Containment (30 min - 2 hours)

| Step | Action | Owner |
|------|--------|-------|
| 2.1 | Isolate compromised host from network (quarantine VLAN) | Net Admin |
| 2.2 | Block C2 IPs/domains at perimeter firewall | Net Admin |
| 2.3 | Block C2 domains at DNS resolver (sinkhole) | Net Admin |
| 2.4 | Disable compromised user accounts | IT Admin |
| 2.5 | Capture network traffic from host | Net Admin |
| 2.6 | Collect memory dump and disk image | IR Team |

---

### Phase 3: Eradication (2-8 hours)

| Step | Action | Owner |
|------|--------|-------|
| 3.1 | Malware analysis (static/dynamic) | Malware Analyst |
| 3.2 | Identify persistence mechanisms | Malware Analyst |
| 3.3 | Remove malware from host | Endpoint Team |
| 3.4 | Remove persistence mechanisms | Endpoint Team |
| 3.4 | Reset all credentials for compromised user | IT Admin |
| 3.5 | Scan network for lateral movement | IR Team |
| 3.6 | Check for data exfiltration | IR Team |

---

### Phase 4: Recovery (1-24 hours)

| Step | Action | Owner |
|------|--------|-------|
| 4.1 | Rebuild compromised host from gold image | IT Admin |
| 4.2 | Restore data from clean backup | DBA / App Owner |
| 4.3 | Re-enable network access with enhanced monitoring | Net Admin |
| 4.3 | Deploy updated AV/EDR signatures | Endpoint Team |

---

### Phase 5: Post-Incident (24-72 hours)

| Step | Action | Owner |
|------|--------|-------|
| 5.1 | Full malware analysis report | Malware Analyst |
| 5.2 | Update detection rules with new IOCs | Sec Engineer |
| 5.2 | Update threat intelligence feeds | Threat Intel |
| 5.3 | Lessons learned meeting | IR Lead |
| 5.4 | Update IR playbooks | IR Lead |

- Network Admin

## Useful Commands Reference

### Forensic Collection
```bash
# Memory dump (Linux)
sudo avml output.lime

# Memory dump (Windows)
winpmem_mini_x64_rc2.exe output.raw

# Disk image
dd if=/dev/sda of=/mnt/evidence/disk.img bs=64K conv=noerror,sync

# Network capture
tcpdump -i eth0 -w capture.pcap -s 0 -G 3600 -W 24

# Process list
ps aux > processes.txt
netstat -tulpn > connections.txt
lsof -i > open_files.txt

# Persistence check
systemctl list-unit-files --state=enabled
crontab -l
ls -la /etc/cron.*/
systemctl list-timers
```

### Evidence Preservation
```bash
# Hash evidence
sha256sum evidence.img > evidence.img.sha256

# Chain of custody
echo "Collected by: $(whoami) on $(date) from $(hostname)" > chain_of_custody.txt
echo "Hash: $(sha256sum evidence.img)" >> chain_of_custody.txt
```
